# apps/worker

ARQ-воркер: фоновые задачи раздела 10.1 ТЗ. Сейчас их пять — две по вызову и
три по расписанию.

По вызову:

- `render_report` — PDF-отчёт (раздел 15 п. 14, ADR-0008);
- `notify_family` — уведомление семьи о новом назначении (раздел 5.4). Текст без
  цифр: параметры назначения бот не показывает (раздел 7.5), их семья смотрит в
  кабинете.

По расписанию:

- `purge_files` — ночная уборка файлов в 03:30 (ADR-0013): просроченные PDF и
  байты удалённых вложений после отсрочки `ATTACHMENT_PURGE_DAYS`. Строки
  остаются, снимаются только байты; отметки об уборке — `attachments.purged_at`
  и обнулённое `report_jobs.file_name`, без них задача каждую ночь заново
  обходила бы одно и то же.
- `close_stuck_ai_jobs` — раз в час закрывает обращения к модели, застрявшие в
  `RUNNING` (процесс воркера умер посреди вызова). Бронь при этом остаётся
  потраченной: деньги ушли. Раз в час, а не ночью, — иначе бронь оборвавшегося
  утром вызова занимала бы бюджет до полуночи.
- `reminders_cron` — напоминания семье (раздел 7.4), каждые пять минут.
  Расписание задаёт семья в кабинете, а не клиника. Окно попадания шире шага на
  минуту: при задержке очереди напоминание не должно пропадать до завтра. Право
  на отправку занимается до вызова Telegram — лучше пропустить напоминание при
  сбое сети, чем прислать его дважды. Если запись за день уже есть, напоминание
  не уходит вовсе.

Задач ИИ здесь пока нет: `parse_free_text` — п. 19 этапа 4, ассистент — п. 20,
сводка врачу и черновики контента — п. 21. Сделана их опора (п. 18) — см. ниже.

Обе задачи по расписанию молчаливы по замыслу: в журнале видно
`cron:purge_files ● {'reports': N, 'attachments': M}` и
`cron:reminders_cron ● {'sent': N, 'skipped': M}`. Нули на свежем стенде — норма,
а не признак поломки.

## ИИ-модуль (`worker/ai`)

Единственная дверь к Claude API — `ai.client.AiClient` (раздел 10.2 ТЗ).
Задачи не обращаются к SDK напрямую: всё, что обязано случаться при каждом
вызове, случается здесь и не зависит от того, вспомнил ли о нём автор задачи.

- **Псевдонимизация.** `pseudonymize(payload)` чистит нагрузку рекурсивно, и
  вызывает её сам клиент — обойти, не переписав клиент, нельзя (правило 6
  `CLAUDE.md`). Пациент превращается в `patient 3f2a1c9d, возраст 5 лет 1 мес,
  пол ж`: возраст, а не дата рождения, потому что дата рождения вместе с полом
  идентифицирует ребёнка.
- **Журнал.** Строка в `ai_jobs` заводится ДО обращения — вызов может не
  вернуться вовсе, а деньги за него спишутся, — и закрывается после, с токенами
  и стоимостью. Неудачный вызов записывается так же, как успешный. В `input`
  лежит уже очищенная нагрузка: иначе ФИО просто переехало бы из промпта в БД.
- **Предохранители.** Дневной бюджет проекта (`AI_DAILY_BUDGET_USD`) считается
  по сумме стоимости за сегодня; суточный предел пользователя
  (`AI_USER_DAILY_LIMIT`) — по числу вопросов **ассистенту** (раздел 10.2 ТЗ).
  Разбор еды пределом пользователя не ограничен: родитель кормит ребёнка
  столько раз, сколько нужно, и упереться в предел посреди дня означало бы
  остаться без функции, ради которой бот и нужен. Сутки — по часовому поясу
  проекта (`TZ`), а не по UTC.
  Проверка и запись строки идут под транзакционной блокировкой
  (`pg_advisory_xact_lock`): без неё это «прочитали, потом записали», и
  одновременные задачи проходят предохранитель разом. Под строку сразу
  **бронируется** верхняя оценка стоимости (по потолку ответа) — пока вызов
  идёт, настоящей цены никто не знает, а без брони оборвавшийся вызов не попал
  бы в бюджет никогда. `mark_done` заменяет бронь фактической ценой.
- **Свободный текст** человека (`user_text`) чистится от контактов
  (`scrub_free_text`) — почта, телефон, ник Telegram. Имена не ищутся: в
  «Аня съела два яйца» имя неотличимо от слова. Решение и остаток риска —
  [ADR-0019](../../docs/adr/0019-free-text-in-ai-prompts.md).
- **Модель — из окружения** (`AI_MODEL_FAST` для разбора, `AI_MODEL_SMART` для
  ассистента и сводки). Пустое значение — отказ, а не подстановка по умолчанию:
  подстановка и есть хардкод модели, запрещённый правилом 6.
- **Цены** — в `ai/pricing.py`, долларов за миллион токенов, сверено с
  <https://platform.claude.com/docs/en/pricing> на 2026-06-24. В окружении их
  нет намеренно: переменная, которую забыли обновить, отключает бюджет молча.
  **Модель, которой нет в таблице, к работе не допускается**: без цены сумма за
  день считалась бы нулём, и дневной бюджет не срабатывал бы никогда — от одной
  опечатки в `.env`. Меняете модель — добавьте её цену; тест проверяет, что
  значения из `.env.example` в прайсе есть.
- **Ретраи** — три, экспоненциально; их делает сам SDK (`max_retries=3`), свой
  цикл поверх чужого дал бы девять попыток.
- **Отказы** различаются типом: `AiLimitExceeded` (в API — `rate_limited`,
  «на сегодня хватит»), `AiUnavailable` (модель не ответила — мягкая деградация
  раздела 10.2), `NotConfigured` (ключа или имени модели нет).

Промпты — файлами в `ai/prompts/*.md`, меняются **отдельным PR** с ревью
человека (раздел 10.4 ТЗ). Клиент промптов не знает: он отвечает за «как
обратиться», а не «о чём».

Тесты ИИ-модуля требуют поднятой БД (`make dev`): журнал — предохранитель, и
проверять его на подделке репозитория значит проверять подделку.

## Запуск

```
make worker
```

Адрес Redis берётся из `core.config.Settings`, то есть из того же `.env`, что
читает API. Своей `BaseSettings` у воркера нет намеренно: она видела бы только
переменные процесса, воркер слушал бы `localhost:6379`, а API ставил задачи в
Redis из `.env` — и очередь никогда бы не сошлась.

## PDF требует системных библиотек

`weasyprint` — обёртка над pango и cairo, и без них печать не работает:

```
OSError: cannot load library 'libgobject-2.0-0'
```

На macOS: `brew install pango libffi`. **Одной установки мало:** библиотеки
ложатся в `/opt/homebrew/lib`, а dyld туда не смотрит при `dlopen` из Python —
weasyprint падает с той же ошибкой при установленных библиотеках. Поэтому
`make worker` выставляет `DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib`.

Второй подвох там же: `make worker` запускает **`python -m arq`**, а не
консольный скрипт `arq`. У скрипта в `.venv/bin` шебанг `#!/bin/sh`, а macOS
вычищает переменные `DYLD_*` при запуске защищённых системой бинарников — до
Python путь к библиотекам не доезжает, и weasyprint падает при установленных
библиотеках. По той же причине тест печати проходит под
`uv run python -m pytest`, а под консольным `pytest` пропускается.

В Debian-образе: `apt-get install libpango-1.0-0 libpangoft2-1.0-0
libharfbuzz0b libffi8`; там переменная не нужна.

Библиотека импортируется **лениво**, внутри функции печати
(`worker/reports/render.py`), поэтому их отсутствие не роняет воркер целиком:
остальные задачи работают, а сборка PDF помечает задачу `failed` с понятной
причиной. По той же причине тесты проверяют HTML отчёта, а не байты PDF: тест,
падающий из-за отсутствия pango, ничего не говорит о правильности отчёта.

## Том отчётов

`REPORTS_DIR` (по умолчанию `./var/reports`) — общий каталог API и воркера:
воркер пишет файл, API отдаёт его по ссылке с истечением
(`REPORT_LINK_TTL_HOURS`). Каталог в `.gitignore`: там лежат клинические данные.
