# База знаний ассистента семьи

Отсюда ассистент берёт всё, что говорит семье (раздел 10.4 ТЗ). Ничего сверх
статей базы знаний он не рассказывает: **не нашлось подходящей статьи — модель
не вызывается вовсе**, и родитель получает шаблонный ответ с предложением
обратиться к врачу.

**С 20.11.2026 статьи живут в кабинете, а не в этом каталоге**
([ADR-0093](../adr/0093-knowledge-base-articles-in-the-cabinet.md)). Файлы здесь
значат теперь разное — см. таблицу ниже.

## Как теперь добавляется статья

| Вид | Где | Кто пишет | Кто публикует |
|---|---|---|---|
| клиническая — болезнь, диета, питание, симптомы, лекарства | кабинет, раздел «Статьи для семей» | врач или диетолог | **другой** врач или диетолог, не автор редакции |
| продуктовая встроенная — как устроено приложение | файл в `product/`, PR | разработка | выпуск приложения |
| продуктовая своя | кабинет, раздел «Статьи о приложении» | администратор | администратор сам |

- **Клиническая статья — по правилу четырёх глаз.** Автор пишет черновик
  (текстом или загружает из Word) и отправляет на проверку; второй специалист
  публикует его или возвращает с комментарием. Свою редакцию опубликовать нельзя
  — это держит сервер. Правка опубликованной статьи заводит новую версию, а
  помощник отвечает по прежней, пока новую не опубликуют. Каждая опубликованная
  версия хранится и не меняется. Снять статью из помощника может любой
  специалист сразу.
- **Администратор клинических статей не видит** — ни перечня, ни черновиков, ни
  их текста в журнале действий (правило 5 `CLAUDE.md`).
- **Встроенные продуктовые статьи** администратор видит на чтение и может скрыть
  из помощника; выпуск скрытую статью не возвращает.
- При отправке на проверку кабинет показывает предложения, которые постфильтр
  помощника заблокировал бы (дозировка, совет изменить терапию, толкование
  симптома, диагноз). Это предупреждение, а не запрет: помощник по такому разделу
  ответит шаблоном «обсудите с врачом».

## Что значат файлы этого каталога

| Каталог | Что это теперь | Правит агент? |
|---|---|---|
| `product/` | **встроенные статьи выпуска**: при каждом выкате приводятся к файлам (новая — опубликована, изменившаяся — новая версия, исчезнувшая — снята) | да |
| `clinical/` | **перенесены в базу один раз** с подписью из заголовка как первой опубликованной версией; дальше их ведут в кабинете, и файл базу **не перезаписывает**. Новый файл здесь не публикуется — выкат только называет его. Удалит их отдельный PR | **нет**, каталог защищён хуком, пока файлы не удалены |
| `clinical-drafts/` | черновики 07.10.2026 из открытых источников; помощник их не видит. Новые статьи сюда не кладутся — их пишут в кабинете | да |

Граница между клиническим и продуктовым по-прежнему проходит не по теме, а по
вопросу «кто отвечает, если это неверно». «Куда вписать кетоны» — продукт.
«Какие кетоны считаются нормой» — клиника, даже если ответ кажется
общеизвестным (правило 1 `CLAUDE.md`).

22.10.2026 клиника одобрила для тестирования 15 клинических статей (приступы,
скрытые углеводы, питьё, полоски мочи, запоры и др.); они и перенесены в базу.

## Формат встроенной статьи

Файл — `<id>.md`, где `id` совпадает с именем файла без расширения. Этот
формат нужен файлам `product/`; статьи кабинета задаются формой. `kind`
обязан совпадать с каталогом: `kind: clinical` в `product/` — ошибка разбора,
и проверка `index_knowledge_base --check` в CI её ловит. Если `id` нового файла уже занят
статьёй кабинета, выкат файл пропустит с предупреждением — переименуйте его.

```
---
id: how-to-record-ketones
title: Как записать кетоны
kind: product            # product | clinical
status: approved         # approved | draft — до модели доезжает только approved
version: 1               # растёт при смысловой правке
source: docs/TZ_AI_AGENTS.md#7.3   # файл или URL, обязательно
approved_by: владелец продукта     # для clinical — ФИО и роль из медкоманды
approved_at: 2026-09-03
---
```

## Как ассистент это использует

1. Вопрос семьи → поиск по кускам опубликованных и не скрытых статей
   (полнотекст PostgreSQL, русская морфология).
2. Ничего не нашлось → **модель не вызывается**, ответ шаблонный.
3. Нашлось → куски уходят в промпт, и модель обязана отвечать только по ним и
   ссылаться на статьи.

Одна статья — одна тема. Резка на куски идёт по заголовкам второго уровня
(вступление до первого раздела — тоже кусок), и каждый кусок несёт заголовок
статьи целиком — так модель всегда видит, откуда взят текст. Индекс собирает
шаг выката (`make kb-index` локально); публикация, снятие и скрытие в кабинете
меняют его сразу.
