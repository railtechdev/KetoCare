# База знаний ассистента семьи

Отсюда ассистент берёт всё, что говорит семье (раздел 10.4 ТЗ). Ничего сверх
этих файлов он не рассказывает: **не нашлось подходящей статьи — модель не
вызывается вовсе**, и родитель получает шаблонный ответ с предложением
обратиться к врачу.

## Два каталога, и разница между ними принципиальная

| Каталог | Что там | Кто утверждает | Правит агент? |
|---|---|---|---|
| `clinical/` | всё про болезнь, диету, питание, симптомы, лекарства | медицинская команда | **нет**, каталог защищён хуком |
| `product/` | как устроено приложение: куда нажать, что показывает экран | владелец продукта | да |

Граница проходит не по теме, а по вопросу «кто отвечает, если это неверно».
«Куда вписать кетоны» — продукт. «Какие кетоны считаются нормой» — клиника,
даже если ответ кажется общеизвестным (правило 1 `CLAUDE.md`).

**Сегодня `clinical/` пуст, и это штатное состояние** (черновики для медкоманды
лежат отдельно, в `clinical-drafts/`, — см. ниже). Утверждённых медицинской
командой материалов в проекте нет ни одного: в `docs/medical/` лежат наши
вопросы и 35 провизорных эталонов. Ассистент от этого не ломается — он работает
навигатором по приложению, а на клинические вопросы отвечает шаблоном. Пустой
каталог оставлен намеренно: отсутствующий выглядел бы как незаконченная работа
и провоцировал наполнить его «медицинским здравым смыслом».

## Третий каталог: `clinical-drafts/` — черновики, которые помощник не видит

С 07.10.2026 рядом лежит `clinical-drafts/`: черновики клинических статей,
собранные из открытых источников (Charlie Foundation, Matthew's Friends,
Epilepsy Foundation, консенсус International Ketogenic Diet Study Group, NICE,
ILAE, ВОЗ, клинические рекомендации Минздрава РФ), — по просьбе заказчика, чтобы
медицинской команде было что читать и править, а не писать с нуля.

Это **не** клинические материалы. Индекс читает только `product/` и
`clinical/` (`core.knowledge.documents.article_paths`, под тестом), поэтому из
черновиков до семьи не доезжает ни слова, что бы ни стояло в их заголовке.
Черновик становится статьёй, только когда медицинская команда его прочитала и
человек перенёс файл в `clinical/` с подписью — агент этого сделать не может,
каталог `clinical/` защищён хуком. Порядок и лист согласования —
[`clinical-drafts/README.md`](clinical-drafts/README.md).

## Формат статьи

Файл — `<id>.md`, где `id` совпадает с именем файла без расширения.

```
---
id: how-to-record-ketones
title: Как записать кетоны
kind: product            # product | clinical
status: approved         # approved | draft — до модели доезжает только approved
version: 1               # растёт при смысловой правке
source: docs/TZ_AI_AGENTS.md#7.3   # файл или URL, обязательно
approved_by: владелец продукта     # для clinical — ФИО и роль из медкоманды
approved_at: 2026-09-03
---
```

выдумываются» становится машинной проверкой.

## Как ассистент это использует

1. Вопрос семьи → поиск по кускам статей (полнотекст PostgreSQL, русская
   морфология).
2. Ничего не нашлось → **модель не вызывается**, ответ шаблонный.
3. Нашлось → куски уходят в промпт, и модель обязана отвечать только по ним и
   ссылаться на статьи.

Один файл — одна тема. Резка на куски идёт по заголовкам второго уровня, и
каждый кусок несёт заголовок статьи целиком — так модель всегда видит, откуда
взят текст.
