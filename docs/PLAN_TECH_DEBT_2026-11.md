### Пакет 2. `ci`: падение расписания заводит issue — 2 часа

**Причина.** `uptime.yml` при отказе открывает issue с меткой и закрывает при
восстановлении — и его падение заметили в тот же день. У `e2e.yml`, `audit.yml` и
`engine-deep.yml` такого нет, и их красный цвет виден только тому, кто откроет вкладку
Actions. Дважды это стоило по две-три недели слепоты.

**Что сделать.**
1. Вынести из `uptime.yml` шаг «открыть / дополнить / закрыть issue по метке» в
   переиспользуемый workflow (`.github/workflows/_report-failure.yml`,
   `workflow_call`) или composite action в `.github/actions/`.
2. Подключить его к `e2e.yml`, `audit.yml`, `engine-deep.yml` с метками `nightly-e2e`,
   `audit`, `engine-deep`; текст issue — ссылка на прогон и список упавших тестов
   (для Playwright — из отчёта `test-results`, он уже выгружается артефактом).
3. Восстановление закрывает issue комментарием, как у `uptime`.
4. Тест на логику сводки — рядом с `infra/tests/test_uptime_check.py`, если логика
   выйдет за пределы пяти строк shell.

**Готово, когда** намеренно сломанный тест на ветке открывает issue, а починка закрывает.
