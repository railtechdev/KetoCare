Составлено 18.09.2026, при переезде на другой компьютер. Здесь то, чего **нет в
коде** и что иначе потеряется: что лежит только на прежней машине, на чём

Состояние кода описывает `CLAUDE.md`, готовность к пациентам — `READINESS.md`.
Этот файл их не повторяет.

## 1. Что НЕ переезжает само — забрать руками

**`~/ketocare-backup.key` — приватный ключ шифрования резервных копий.** Лежит
только на прежней машине, создан 17.09.2026, на сервер не попадает намеренно.

**Без него ни одну резервную копию не расшифровать. Никогда, ничем.** Копии на
сервере зашифрованы им (`/srv/backups/*.age`), внешнего хранилища нет
(решение заказчика — см. `READINESS.md`), и снимки провайдера после сдачи
шифрование не отменяют.

Что сделать: скопировать файл в менеджер паролей, затем удалить из домашнего
каталога прежней машины. Проверить, что копия рабочая, можно на любой машине с
поднятой локальной базой:

```bash
BACKUP_AGE_IDENTITY=<путь к ключу> \
  infra/scripts/verify-backup.sh <файл>.age ketocare-dev-postgres-1
```

Ожидаемый ответ — «Восстановление проверено», 43 таблицы, версия схемы совпадает
с выкаченной. Так это проверялось 17.09.2026 на настоящей копии стенда.

**Временный ключ доступа к серверу** (`ketocare-stand-setup-2026-09-17-temporary`)
жил в каталоге сессии и её не переживёт. Он и не нужен: постоянного доступа к
серверу у агента нет по построению — правки идут через репозиторий и выкат.
**Строку с ним надо убрать из `~/.ssh/authorized_keys` пользователя root:**

```bash
ssh root@189.74.96.24 "sed -i '/ketocare-stand-setup-2026-09-17-temporary/d' ~/.ssh/authorized_keys"
```

**Память агента** (`~/.claude/projects/.../memory/`, 40 записей) остаётся на
прежней машине. Переносить её не обязательно: всё, что нужно для работы,
записано в репозитории — `CLAUDE.md`, `docs/UI_GUIDE.md`, ADR и разборы. Память
хранит сведения о машине и привычках, а не о продукте.

## 4. Чем проверять, что среда на новой машине поднялась

```bash
make setup        # свежий клон
make dev          # postgres и redis
make test         # 1846 pytest + 993 vitest на 18.09.2026
make lint
```

Порты объявлены один раз в корневом файле окружения; его на новой машине
придётся создать из `.env.example` и заполнить (секреты редактирует человек —
это правило, а не неудобство).

Сквозной прогон и Mini App:

```bash
make e2e          # 10 сценариев; нужен поднятый make dev
make miniapp-link # подписанная ссылка, чтобы открыть Mini App локально
```

## 5. Три ловушки этой недели, которые стоит помнить

Они уже стоили по прогону каждая и записаны в соответствующих местах, но здесь
собраны вместе — это самое дорогое знание, добытое за эти дни.

- **Документ против кода.** Инструкция по nginx снесла бы TLS на сервере, где
  уже отработал certbot; `verify-backup.sh` удалял расшифрованный дамп за
  секунду до разворачивания; абзац в `CLAUDE.md` про незаконченный переезд на
  кит месяц вводил в заблуждение. Каждый раз механизм существовал, выглядел
  проверенным и не работал. Проверять прогоном, а не чтением.
- **Правило без исполняемой проверки не выполняется даже автором.** Правило П45
  прямо называет кетоны — и кетоны печатались через точку рядом с весом через
  запятую, потому что сторож ловил только `toFixed`.
- **Красный, которому перестают верить, хуже отсутствующего.** Два выката из
  пяти были помечены красным при живом стенде из-за транзита до Узбекистана;
  прежде чем чинить — двенадцать замеров, логи, нагрузка, повтор того же
  коммита.
