# 0008. Таблица `report_jobs` под сборку PDF-отчёта

## Контекст

Раздел 5.3 ТЗ описывает выдачу PDF так: «PDF собирает worker (задача
`render_report`), ручка возвращает job id + polling `GET /reports/jobs/{id}}`».
Раздел 7.5 добавляет: «HTML-шаблон (jinja2) → weasyprint → файл в volume,
ссылка с истечением».

Где живёт состояние этой задачи, ТЗ не говорит. Раздел 4.2 перечисляет 31
таблицу, и подходящей среди них нет: `ai_jobs` описывает вызовы Claude
(`kind` — `assistant`, `parse_meal`, `parse_event`, `doctor_summary`,
`content_draft`), а сборка PDF к ИИ отношения не имеет — класть её туда значило
бы, что счётчики токенов и стоимости у половины строк пустые, а `kind` перестаёт
означать «что просили у модели».

## Решение

Заводится таблица `report_jobs`: `patient_id`, `requested_by`, `period_start`,
`period_end`, `status`, `file_name`, `error`, `expires_at`, `finished_at`.

Почему не хватает состояния очереди ARQ:

1. **Право на скачивание.** Файл содержит клинические данные, и по
   идентификатору задачи нужно проверить `require_patient_access`. Значит,
   пациент задачи должен храниться там, где его нельзя потерять.
2. **Redis эфемерен.** Результаты ARQ живут ограниченное время и исчезают при
   очистке; ссылка, выданная врачу утром, должна работать и днём.
3. **Срок ссылки.** «Ссылка с истечением» из раздела 7.5 требует где-то помнить
   момент истечения и уметь найти просроченные файлы для уборки.
4. **След.** Выгрузка данных — событие для `audit_log` (правило 7). Журнал
   отвечает на вопрос «кто забрал», таблица задач — на вопрос «что именно
   собиралось и живо ли ещё».

Имя файла хранится без пути: путь задаётся настройкой, и отчёт, собранный на
одной машине, не должен ссылаться на её каталоги.

Строки не удаляются вместе с файлами: по журналу должно быть видно, что отчёт
заказывали, даже когда файла уже нет.

## Последствия

- Раздел 4.2 ТЗ дополняется таблицей `report_jobs`; расхождение зафиксировано
  здесь.
- Появляется эксплуатационный параметр — том под отчёты и срок жизни ссылки;
  оба выносятся в переменные окружения (раздел 12 ТЗ).
