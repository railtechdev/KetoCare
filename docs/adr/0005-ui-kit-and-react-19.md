# 0005. shadcn/ui как основа интерфейса, палитра референса и переход на React 19

## Контекст

Заказчик выбрал референс интерфейса и поставил условие: без кастома и костылей,
максимально на возможностях UI-кита из коробки. Разбор показал, что **кита в проекте
не было**: раздел 8.2 ТЗ предписывает Tailwind 4 + shadcn/ui, но `components.json`
отсутствовал, `class-variance-authority` не стоял, а шесть общих компонентов, поля форм
и таблица были написаны руками. Интерфейс целиком состоял из кастома — ровно того,
чего просили избегать.

## Решения

### 1. Ставим shadcn/ui и переносим на него интерфейс

25 компонентов добавлены командой `shadcn add` в `packages/ui/src/components/ui`, чтобы
Mini App этапа 3 взял их же. Алиас заведён отдельным именем `@ui/*`, а не привычным
`@/*`: приложение сохраняет право на собственный алиас, и импорт не становится
двусмысленным.

Своими остались только предметные компоненты, аналогов которым в ките нет:
`RatioBadge`, `MacroBar`, `TrendChart` с маркерами смены назначения, `DiaryEntryCard`.

### 2. Словарь токенов — как у кита

Переименовано в 74 файлах: `canvas` → `background`, `surface` → `card`, `ink` →
`foreground`, `muted` → `muted-foreground`, `line` → `border`, `accent` → `primary`,
`danger` → `destructive`.

Это не косметика. В нашем словаре `bg-accent` означал фирменный цвет, а в словаре кита
— подсветку при наведении. Компоненты кита красились фирменным цветом там, где ждали
едва заметную заливку. Два словаря на один набор CSS-переменных несовместимы в
принципе; выбран словарь кита, потому что его компонентов больше и обновляются они не
нами.

Сверх словаря кита оставлены роли, которых в нём нет: `warning`, `success` и
минимальная тач-цель раздела 8.2.

### 3. Палитра из референса — с поправкой на контраст

Отступление от раздела 8.2, задающего шалфейно-бежевую палитру: заказчик выбрал
сине-синевато-серую с референса.

Значения не скопированы пипеткой. Акцентный синий референса с белым текстом даёт около
4:1 при требовании раздела 8.2 не ниже 4.5:1, поэтому взят более тёмный оттенок того же
тона (5.5:1). Проверок контраста стало 26 против 12: добавлены пары, которых раньше не
проверяли, — приглушённый текст на карточке и на приглушённой подложке, выбранный пункт
навигации, текст на вторичной подложке.

### 4. React 18 → 19

Отступление от раздела 3 ТЗ, где указан React 18.

Компоненты shadcn/ui написаны для React 19, где `ref` — обычное свойство. В React 18
`ref` у функционального компонента отбрасывается, и это не теория: браузер выдавал
«Function components cannot be given refs» для `Input`, `Button` и триггеров Radix, а
форма профиля молча не заполнялась значениями — то есть **любая форма на компонентах
кита теряла бы введённое, не показывая ошибки**.

Альтернатива — обернуть каждый компонент кита в `forwardRef` — означала бы правку
вендорного кода, который перезаписывается следующим `shadcn add`. Это и есть костыль,
которого просили избежать, причём вечный.

Совместимость проверена до обновления: `recharts`, `@tanstack/react-router`,
`@tanstack/react-query`, `@tanstack/react-table`, `react-hook-form`,
`@testing-library/react`, `react-i18next`, `react-day-picker`, `cmdk` — все объявляют
поддержку React 19.

### 5. Мелкие поправки к киту

- `sonner` кита берёт тему из `next-themes` (Next.js). Источник заменён на наш атрибут
  `data-theme`, которым Mini App подставляет тему Telegram; зависимость удалена.
- Файлы кита исключены из правила `react-refresh/only-export-components`: их
  обновляет `shadcn add`, ручная правка была бы затёрта. Остальные проверки для них
  работают как везде.

## Последствия

- Разделы 3 и 8.2 ТЗ разошлись с кодом по версии React и по палитре. Расхождение
  зафиксировано здесь; при обновлении ТЗ эти два пункта нужно привести в соответствие.
- Обновление кита выполняется командой `shadcn add <компонент> --overwrite`. Править
  файлы в `components/ui` руками нельзя — правка не переживёт обновления. Исключение
  (sonner) описано выше и должно проверяться при каждом обновлении.
- Тач-цель 44 px раздела 8.2 у компонентов кита меньше по умолчанию; там, где
  интерфейс родительский, размер задаётся классом `min-h-touch` явно.
