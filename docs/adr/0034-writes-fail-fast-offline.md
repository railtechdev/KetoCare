# ADR-0034. Записи без сети отказывают сразу

- Статус: принято
- Дата: 2026-09-12

## Контекст

Кабинет и Mini App ходят в API через TanStack Query. По умолчанию мутация без
сети встаёт на паузу (`networkMode: "online"`) и отправляется, когда связь
вернётся. Для записей в KetoCare — дневники, меню, назначения, блюда,
приглашения — у этого поведения нет ни одного условия, при котором оно честно:

- очередь живёт в памяти вкладки: закрыл вкладку — запись пропала, и человек об
  этом не узнал;
- после возврата связи запись уходит с экрана, которого может уже не быть: ни
  подтверждения, ни перехода, ни ошибки;
- повторное нажатие, пока первая запись на паузе, отправляет вторую такую же;
- экран всё это время показывает «Сохраняем…» без причины.

Офлайн-режим с очередью (TanStack Query `persistQueryClient` +
`resumePausedMutations`, IndexedDB, видимый список «ждёт отправки», разбор
конфликтов) — отдельный продукт, и медицинские данные ребёнка в нём требуют
решения о конфликтах, которого нет.

Вопрос технический, а не медицинский: решение принято по документации TanStack
Query («Network Mode») и практике веб-приложений без офлайн-режима — запись без
сети получает немедленный отказ, который человек видит и повторяет сам.

## Решение

- `mutations.networkMode: "always"` по умолчанию в обоих приложениях
  (`apps/web/src/lib/queryClient.ts`, `apps/miniapp/src/lib/queryClient.ts`):
  без сети запрос уходит сразу и сразу получает отказ.
- Отказ сети называется в одном месте — `errorMessageOf` в `lib/api.ts`
  возвращает «Нет связи с сервером. Проверьте подключение.» для `NetworkError`
  (класс клиента API, #162). Формы, которые показывают «сообщение сервера или
  „что-то пошло не так“», называют обрыв связи без правок.
- Расчёты — проверка состава, подбор граммовки, пересчёт порций — не записи:
  ничего не сохраняют и ждут связи по замыслу, со строкой ожидания на экране
  (#156, #159–#161). Их режим закреплён явно (`networkMode: "online"`).
- Вход в Mini App без сети отдаёт экран «не удалось открыть» с просьбой
  проверить связь, а не бесконечное открытие.

## Последствия

- Без сети ни одна запись не создаётся «потом». Потерянных и молча
  отправленных записей больше нет; повторяет человек.
- Дубль при потерянном ОТВЕТЕ (сервер записал, ответ не дошёл) этим не
  закрывается — нужен ключ идемпотентности на сервере, отдельной задачей.
- Если когда-нибудь понадобится настоящий офлайн-режим, он заменяет это
  решение целиком: очередь на диске, видимое «ждёт отправки» и разбор
  конфликтов, а не пауза в памяти вкладки.
