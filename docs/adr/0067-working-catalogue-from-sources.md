# ADR-0067. Рабочий справочник из нескольких источников

Дата: 2026-11-11. Статус: принято (заказчик и клиника, 11.11.2026). План —
`docs/PLAN_WORKING_CATALOGUE_2026-11.md`.

## Контекст

Клиника прислала 77 продуктов из руководства по питанию Минздрава РУз. В руководстве нет клетчатки, а у 34
продуктов прочерк в углеводах и у 8 — в жирах. Кетосоотношение считается по чистым углеводам (ADR-0030), и
без клетчатки и с прочерками расчёт ребёнку недостоверен. Рецепты клиники при этом составлены по USDA.

## Решение

1. **Источники — закрытые стандарты** вида `reference` (ADR-0056): Минздрав РУз и USDA. Значения в них не
   правит никто.
2. **Рабочий справочник — стандарт клиники.** У каждого числа продукта хранится источник: запись
   стандарта-источника или правка человека (`products.value_sources`).
3. **Слияние** собирает строку рабочего справочника по порядку источников: местное руководство первым, USDA
   для того, чего в нём нет. Прочерк — «нет данных», он берётся из следующего источника.
4. **Проверка 9–4–4.** Числа из разных источников могут не сойтись по калорийности. Такая строка
   в рабочий справочник сама не попадает, её подтверждает диетолог.
5. **Правка диетолога сильнее слияния.** Исправленное число получает источник «правка человека», повторное
   слияние его не перезаписывает, а показывает расхождение.

## Последствия

- Связь Минздрав ↔ USDA держится на таблице соответствий названий. Пропущенное совпадение оставит поле без
  значения, поэтому таблицу подтверждает диетолог.
- Ядро не меняется: оно получает те же числа на 100 г.
- Прежние продукты стандарта клиники получают источник «целиком из `source`» и ведут себя как раньше.
