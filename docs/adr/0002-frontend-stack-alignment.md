# 0002. Приведение фронтенда к стеку раздела 3 ТЗ

## Контекст

Первая версия `packages/ui` и `apps/web` была написана на рукописном CSS с
БЭМ-подобными классами, тогда как раздел 3 ТЗ предписывает **Tailwind CSS 4 +
shadcn/ui (Radix)**, TanStack Router/Query/Table, react-hook-form + zod, Recharts.
Отступление не было зафиксировано ADR, как того требует раздел 2.3.

Аудит перед началом пп. 10–14 показал, что расхождение породило и прямые дефекты:

- `@tanstack/react-router` стоял в зависимостях, но **не использовался**: навигация
  шла обычными `<a href>`. Каждый переход по меню перезагружал страницу, а вместе с
  ней терялся access-токен, который по соображениям безопасности живёт только в
  памяти вкладки — на каждый клик уходил лишний `POST /auth/refresh`.
- `@tanstack/react-query` был подключён только провайдером; запросы шли вручную
  через `useState`/`useEffect`, вопреки разделу 8.4 ТЗ.
- `cn()` использовал `tailwind-merge` — библиотеку, существующую ровно для
  разрешения конфликтов Tailwind-классов. Без Tailwind она бессмысленна, и код
  создавал ложное впечатление, что проект уже на Tailwind.
- В `TotpSetupForm` стоял `// eslint-disable-next-line react-hooks/exhaustive-deps`
  при том, что eslint в проекте вообще не был настроен: комментарий отключал
  правило несуществующего линтера и маскировал реальную проблему зависимостей.

## Решение

Привести фронтенд к ТЗ, а не фиксировать отступление.

Ключевой довод — доступность. Раздел 8.2 требует focus-visible, aria-разметку,
контраст ≥ 4.5:1 и тач-цели ≥ 44 px. Radix даёт проверенные примитивы с ловушкой
фокуса, клавиатурной навигацией и корректными ARIA-ролями; писать это руками —
переизобретать чужую работу и повторять её ошибки в интерфейсе, которым родители
пользуются при расчёте питания ребёнка.

Момент выбран сознательно: на день принятия решения компонентов было четыре.
После пп. 10–14 их были бы десятки.

## Последствия

- Токены дизайн-системы переехали из `:root` в `@theme` Tailwind 4 (конфигурация
  из CSS, без `tailwind.config.js`). Палитра, радиус и шрифт раздела 8.2 не
  изменились; тест `contrast.test.ts` по-прежнему читает значения из самого
  `tokens.css` и проверяет контраст в обеих темах.
- Тёмная тема включается атрибутом `[data-theme="dark"]` через `@custom-variant`:
  Mini App выбирает её по themeParams Telegram, а не по настройке ОС.
- Навигация переведена на TanStack Router с типизированным маршрутом
  `/app/$section`. Список разделов зависит от роли, поэтому генерация путей
  строками обходила бы типизацию роутера — вместо набора статических маршрутов
  используется один параметризованный с проверкой в `beforeLoad`.
- Формы переведены на react-hook-form + zod, запросы — на TanStack Query.
- Настроен eslint (flat config в корне) и включён в `make lint` и CI.
- `cn()` с `tailwind-merge` сохранён: с появлением Tailwind он выполняет ту
  работу, ради которой предназначен.

Отдельно зафиксировано: guard'ы роутера — это UX, а не безопасность. Доступ к
данным пациента проверяет сервер на каждом запросе (правило 5 `CLAUDE.md`);
роутер лишь не показывает заведомо недоступные разделы.

## Не сделано этим решением

`DataTable` и `TrendChart` (обязательные компоненты раздела 8.2) появятся вместе
с экранами, которые их используют: `@tanstack/react-table` и `recharts` уже
установлены, но компоненты без реальных данных спроектировать нельзя.
