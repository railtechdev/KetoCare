# 0010. Калькулятор, справочник продуктов и план питания у врача

## Контекст

Раздел 8.1 ТЗ задаёт состав разделов по ролям:

```
/app (doctor)   : patients | patients/:id (overview, prescription, medications, diary, reports, notes) | summaries
```

То есть врачу отведены список пациентов, карта пациента и сводки. Ни калькулятора,
ни справочника продуктов, ни рецептов. При этом:

- **Диетолог** те же продукты и рецепты **редактирует** — сервер даёт ему запись
  (`products.py`, `_EDITOR_ROLES = (ADMIN, DIETITIAN)`), и разделы у него в меню есть.
- **Врач** назначает кетосоотношение и суточную калорийность, но проверить, выполнимо
  ли назначение на продуктах, доступных семье, ему нечем.
- **Плана питания** врач не видел вовсе. В карте были дневник «Питание» (что семья
  записала съеденным) и итоги дня числами; из каких блюд и по сколько граммов
  набирается назначенное соотношение — не показывалось нигде.

Последнее существеннее прочего: врач, ведущий кетотерапию, судит об исполнении
назначения по итоговым числам, не видя состава, который эти числа даёт. Расхождение
между планом и назначением он замечает только постфактум, по вердикту о допусках.

Права на сервере при этом уже есть: `GET /products` открыт любой аутентифицированной
роли, `/calc/*` — тоже, `GET /patients/{id}/menus` защищён `require_patient_access`,
то есть врачу с доступом к пациенту открыт. Ни одна новая привилегия не появляется.

## Решение

1. **Врачу добавлены разделы `calculator` и `products`** — на чтение и расчёт.
   Рецепты не добавлены: врач их не редактирует, а как справочник блюд они дублируют
   продукты; вернуться к вопросу, если появится запрос от врачей.

2. **В карту пациента добавлена вкладка «Питание»** — план дня на чтение: приёмы
   пищи, блюда, множитель порции, отметка семьи «съедено», итоги дня против
   назначения.

3. **Вкладка именно на чтение.** Сервер правку специалисту не запрещает, но менять
   план семьи за её спиной — не работа врача: расхождение между тем, что семья видит
   на кухне, и тем, что кто-то поправил из кабинета, — клинический риск. Врач меняет
   назначение, семья перестраивает меню.

4. **Выбор пациента предлагается в самом экране.** Калькулятор и меню показывают
   данные одного ребёнка (`PatientGate`). Переключатель в шапке есть только у
   родителя, поэтому пустое состояние «выберите ребёнка» теперь содержит список
   доступных — иначе врач, открывший калькулятор из меню, упирался бы в сообщение без
   выхода. Это заодно закрывает тот же тупик у родителя двоих детей.

## Последствия

- Расхождение с разделом 8.1 ТЗ зафиксировано здесь; при обновлении ТЗ состав
  разделов врача привести в соответствие.
- Диетолог получает те же разделы: он и раньше имел `products` и `recipes`, теперь у
  него есть и калькулятор — он назначения тоже создаёт (`prescriptions.py`).
- Новых ручек и новых прав не потребовалось.
