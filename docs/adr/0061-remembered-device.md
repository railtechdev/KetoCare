# ADR-0061. Запомненное устройство

Статус: принято, 10.11.2026, по решению заказчика. Отступает от раздела 5.2 ТЗ («для admin/doctor/dietitian вход =
пароль → код»).

## Контекст

Медики попросили упростить вход: код из приложения-аутентификатора они вводят каждый рабочий день, потому что
сессия сотрудника живёт 12 часов. Они предложили вход только по паролю или кодом на почту. Пароль без второго
фактора открывал бы медицинские данные детей, а отправки почты в продукте нет.

## Решение

1. На шаге кода есть «Запомнить это устройство на 30 дней». После верного кода браузер получает случайный токен в
   куке `trusted_device`: httpOnly, secure, `SameSite=Strict`, путь только `/api/v1/auth`. В базе хранится его sha256.
2. На запомненном устройстве вход идёт по паролю, код не спрашивается. Пароль, порог неудач и журнал прежние, запись
   входа помечается `trusted_device`.
3. Устройство привязано к текущему паролю и секрету второго фактора: смена любого из них, включая сброс
   администратором, делает все запомненные устройства недействительными без отдельных правок в каждом месте.
4. В профиле «Забыть все устройства» снимает доверие сразу, действие пишется в журнал.
5. Срок 30 дней — верхняя граница повторной проверки второго фактора для AAL2 в NIST SP 800-63B (§4.2.3).

## Последствия

- Укравший пароль и сам браузер врача входит без кода. Это та же цена, что у открытой сессии на чужом компьютере;
  запоминать устройство на общих компьютерах не нужно, подпись это не объясняет, это задача обучения.
- Код на почту и вход только по паролю не сделаны.
