# ADR-0080. Ключ, модели, бюджеты и лимиты ИИ — в кабинете администратора

- Статус: принято
- Дата: 2026-11-14
- Связано: раздел 10.2 ТЗ, правило 6 `CLAUDE.md`, [аудит архитектуры](../AUDIT_ARCHITECTURE_2026-11.md) (этап 1), ADR-0019, ADR-0079

## Контекст

Ключ поставщика ИИ, имена моделей, дневной бюджет и предел на человека жили в
секретах и переменных репозитория (раздел 10.2 ТЗ: «имена моделей из env»).
Сменить любое значение мог только тот, у кого есть доступ к настройкам
репозитория, и только выкатом. Заказчик попросил вводить ключ из админки,
выбирать модели отдельно для технических работ, специалистов и семей, ставить
лимиты и видеть расход.

Второй довод — общий бюджет. Чтение сборника рецептов (ADR-0079) — десятки
обращений; диетолог, загрузившая большой файл, могла исчерпать дневной бюджет
проекта, и помощник семьи до утра отвечал бы «лимит исчерпан».

## Решение

1. **Таблица `app_settings`** (ключ → JSON) и реестр в `core.app_settings`: у
   каждой настройки тип, границы и значение по умолчанию. **Окружение остаётся
   запасным**: пустая таблица — стенд работает ровно как до неё, строка в
   кабинете побеждает переменную. API и воркер читают таблицу с кэшем на 30 с:
   правка доходит до фоновых задач без перезапуска.
2. **Три группы задач** (`AI_TASKS`), у каждой — модель (и быстрая модель у
   семей, для синхронного разбора текста), дневной и месячный бюджет, предел
   обращений на человека в сутки, выключатель:

   | Группа | Задачи |
   |---|---|
   | Технические работы | черновик карточки рецепта, чтение файла рецептов |
   | Специалисты | сводка для врача |
   | Семьи | помощник, разбор еды и события из текста |

   Бюджет группы её собственный и не занимается другой группой. Бюджет
   проекта (день и месяц) — общий потолок над всеми. Пустой бюджет группы —
   «своего потолка нет, тратит из бюджета проекта»: так ведёт себя и стенд до
   решения заказчика о делении денег (вопрос 3 раздела 4.5 аудита).
   Предел на человека считает только интерактивные задачи группы: разбор еды
   (родитель кормит ребёнка столько раз, сколько нужно) и чтение файла (один
   сборник — десятки обращений) под него не попадают, как и прежде.
3. **Ключ хранится зашифрованным** (`core.secret_box`, Fernet из
   `cryptography`, не самописное шифрование). Ключ шифрования —
   `SETTINGS_ENCRYPTION_KEY`, а если он пуст — выводится из `SECRET_KEY` через
   HKDF со своей меткой. Ключ ИИ в кабинете только записывается: ответ API
   несёт последние четыре знака, дату и автора замены. Зашифрованное другим
   ключом читается как «нет»: работает ключ из окружения, а кабинет говорит,
   что введённый ключ надо ввести заново.
4. **Проверка ключа** — запрос списка моделей поставщика (`GET /v1/models`):
   бесплатно, без строки в `ai_jobs` и без обращения к модели. Отвечает, принят
   ли ключ и какие модели из прайс-листа он открывает. Это не вызов модели, и
   правило «единственной двери» (`AiClient`) он не нарушает — SDK
   по-прежнему импортирует только клиент.
5. **Модель выбирается только из прайс-листа.** Цены переехали из воркера в
   `core.ai_pricing`: тем же списком проверяется выбор в кабинете. Модель без
   цены обнулила бы бюджет (довод из `pricing.py` остаётся в силе). Модель,
   выбывшая из прайс-листа после сохранения, не роняет группу: та возвращается к
   модели из окружения.
6. **Журнал аудита**: каждая правка — `update` над сущностью `app_settings`
   со снимком «было/стало»; ключ — `ai_key_replaced` / `ai_key_removed` только
   с последними четырьмя знаками.
7. **Выключенная группа** — `AiDisabled`, подкласс `NotConfigured`: каждая
   задача уже отвечает на него человеческим «сейчас недоступно».

## Последствия

- Раздел 10.2 ТЗ («имена моделей из env») заменён: имена — из кабинета, env —
  запасной путь. Правило 6 `CLAUDE.md` не нарушено: в коде моделей по-прежнему
  нет.
- Предел на человека считается по группе: врач, делающий сводки и черновики
  карточек, получает по пределу на каждую группу, а не один общий.
- Взлом учётной записи администратора становится кражей ключа и чужим
  расходом. Второй фактор у персонала обязателен и отключить его нельзя; бюджет
  по умолчанию конечен. Уведомления о замене ключа нет — отправки почты в
  продукте нет, и администраторы не привязаны к Telegram; замена видна в
  журнале действий.
- Смена `SECRET_KEY` без `SETTINGS_ENCRYPTION_KEY` делает введённый ключ
  нечитаемым; ИИ при этом не ложится, если ключ есть в окружении.
- Экрана «кто сколько потратил» здесь нет — только суммы по группам. Разрезы по
  людям и видам, предупреждения при 80 % бюджета — этап 2 аудита.
