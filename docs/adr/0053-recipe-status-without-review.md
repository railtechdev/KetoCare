# ADR-0053. Статус рецепта без «на проверке»

Дата: 2026-10-05. Статус: принято. Основание — ответ клиники на вопрос 32
(09.09.2026).

## Контекст

ТЗ §4.2 объявляет у `recipes.status` три значения: `draft | reviewed | published`.
Перехода в `reviewed` ТЗ не описывает, и в коде его не было никогда: рецепт
создаётся черновиком, публикуется и снимается с публикации обратно в черновик.
Значение жило в перечислении, в типе базы и в словаре кабинета («На проверке»),
то есть интерфейс умел показать состояние, в которое ничто не переводит
(`docs/AUDIT_JOURNEY.md`, находка «Статус рецепта „На проверке“ недостижим»).

Клиника ответила на вопрос 32: проверка рецепта перед публикацией не нужна, если
рецепт назначен врачом или диетологом. Рецепты в базе заводят и публикуют
диетолог и администратор клиники; это решение их права не меняет — убирается
только значение, в которое ничто не переводило.

## Решение

Значение `reviewed` убрано целиком: из `RecipeStatus`, из словаря кабинета и из
типа PostgreSQL `recipe_status` (ревизия `801c8afc64d3`). Тип пересоздаётся —
убрать значение из перечисления PostgreSQL иначе нельзя. Строк с этим статусом
быть не может (производителя нет), но если ручная правка базы такую оставила,
миграция переводит её в черновик: черновик семьи не видят, и публикует его снова
человек.

Оставить значение в базе и убрать только из кода было бы хуже: тип базы и
перечисление приложения разошлись бы, а строка с `reviewed` роняла бы чтение
рецепта ошибкой ORM.

## Последствия

- Статусов рецепта два: `draft` и `published`. Переходы прежние: публикация и
  снятие с публикации.
- Если шаг рецензирования когда-нибудь понадобится, он заводится заново вместе с
  переходом, ролью проверяющего и миграцией — значение без перехода не
  возвращается.
- Откат ревизии возвращает значение в тип без потерь.
