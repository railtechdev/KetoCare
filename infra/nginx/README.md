# nginx перед KetoCare API

## Заголовки адреса клиента

`audit_log.ip` и ключ ограничения частоты на `/auth/*` берутся из адреса клиента,
поэтому подмена заголовка ломает и журнал доступа к клиническим данным, и защиту от
перебора паролей. Разрешение адреса выполняет **только приложение**, по списку
`TRUSTED_PROXY_IPS`.

Из этого следуют два обязательных требования.

**1. nginx перезаписывает `X-Forwarded-For`, а не дописывает.**

```nginx
proxy_set_header X-Forwarded-For $remote_addr;   # именно set, не $proxy_add_x_forwarded_for
proxy_set_header X-Real-IP       $remote_addr;
proxy_set_header Host            $host;
proxy_set_header X-Forwarded-Proto $scheme;
```

`$proxy_add_x_forwarded_for` дописывает к тому, что прислал клиент, — тогда первым
элементом останется значение, выбранное клиентом, а приложение берёт именно первый.

**2. uvicorn запускается с `--no-proxy-headers`.**

Иначе uvicorn сам перепишет `request.client` из заголовка (по умолчанию доверяя
`127.0.0.1`), и приложение получит уже подменённый адрес — до того, как проверит
`TRUSTED_PROXY_IPS`. Два слоя, решающих одну задачу по разным правилам, дают дыру.

**3. В `.env` перечислены адреса, с которых приходит трафик от nginx:**

```
TRUSTED_PROXY_IPS=10.0.0.5
```

Пустое значение (по умолчанию) означает «не доверять заголовку никогда» и брать
адрес непосредственного TCP-пира — безопасный вариант для запуска без прокси.
