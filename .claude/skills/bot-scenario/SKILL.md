# Бот — паттерн сценария

## Архитектура

- aiogram 3. Сценарии ввода — `apps/bot/src/bot/handlers/scenarios.py`
  (StatesGroup на сценарий: `Seizure`, `Ketones`, `Weight`, `Meal`, `Medication`,
  `Wellbeing`), привязка — `handlers/start.py`, всё прочее — `handlers/fallback.py`.
- Бот НЕ ходит в БД. Только API, и только через один модуль `apps/bot/src/bot/api.py`.
- Аутентификация **двухключевая** (ADR-0009): сервисный токен `BOT_API_TOKEN`
  (заголовок `X-Bot-Token`) сам по себе открывает только привязку и обмен; вместе
  с **секретом привязки** чата он меняется на access-токен, суженный до одного
  ребёнка (`patient_scope`). Секрет лежит в Redis (`storage.py`) — его терять
  нельзя; сессии в памяти — можно.
- Боту открыт только перечень маршрутов **`BOT_ALLOWED_ROUTES`**
  (`apps/api/src/api/deps/bot.py`), список разрешающий. Новый вызов из бота =
  строка в этом списке + тест в `apps/api/tests`, называющий бота потребителем.
  Тест бота на подделке API стык не проверяет: так кнопка «Лекарства» с первого
  дня отвечала «не удалось сохранить» — маршрута не было в списке.
- Все тексты — ТОЛЬКО в каталогах `apps/bot/src/bot/texts_ru.py` и
  `texts_uz.py` (ADR-0052): одно имя, те же `{подстановки}`, в обоих сразу —
  иначе падает `tests/test_language.py`. Хендлеры читают `texts.X`: модуль
  отдаёт строку на языке текущего обновления. Фильтр кнопки —
  `F.text.in_(i18n.variants("BTN_…"))`, а не `F.text == texts.BTN_…`: старая
  клавиатура на другом языке обязана работать. Строка в хендлере = ошибка
  ревью. Тексты продуктовые (как пользоваться, подтверждения, напоминания,
  доступ) — их пишет и меняет разработка (решение заказчика 05.10.2026).
  Подписи клиники требует только клиническое утверждение — что делать с
  ребёнком, как толковать значение; таких в боте быть не должно (ТЗ §7.5).

## Шаблон сценария

1. Вход — кнопка главного ReplyKeyboard. Кнопка меню всегда побеждает
   незаконченный сценарий.
2. 2–4 шага, инлайн-кнопки где возможно, на каждом шаге кнопка «Отмена» (сброс FSM).
3. Валидация чисел с переспросом: кетоны 0–12 ммоль/л, вес 2–150 кг. Длительность
   приступа — шкала из справочника `intake_options` (та же, что в анкете,
   ADR-0020); интервал со слов в секунды не пересчитывается.
4. Финал: POST в API → подтверждение с эхом введённого → сброс FSM. **`source`
   бот не передаёт**: канал записи ставит сервер по токену (`bot`).
   Запрос несёт `Idempotency-Key` и повторяется при обрыве связи (ADR-0035).
5. Ошибка API → «Не получилось сохранить, попробуйте ещё раз», данные шага не терять.

## Сценарий «Еда» (особый)

«Из меню на сегодня» → позиции дня кнопками → отметка eaten.
«Написать словами» → свободный текст → POST /ai/parse → разобранное названиями и
граммами → Подтвердить / Исправить / Отмена. Сохранение ТОЛЬКО после
«Подтвердить», и в `POST /logs/meals` уходит `ai_job_id`, а не структура: её
сервер берёт из журнала сам. AI недоступен → предложи выбор из меню, не падай.

## Запреты (ТЗ §7.5)

Бот не показывает параметры назначения, не считает, не отвечает на медицинские
вопросы. Нераспознанный текст вне FSM → стандартный ответ из texts.py со ссылкой
на Mini App и напоминанием обратиться к врачу. Выдавать коды доступа и закрывать
доступ из бота нельзя — сервер отвечает 403.

## Напоминания

Логика и отправка — в worker (`worker/reminders`, `reminders_cron` каждые 5 мин,
сутки — по `TZ` проекта): воркер шлёт сообщение в Telegram сам, бот в этом не
участвует. Время напоминаний семья настраивает в **Mini App** (блок
«Напоминания» на главной) или в кабинете — не в боте (ADR-0044). Умолчания
приходят с сервера; «нет записей за день» — одно, мягкое, и только если записи
за день ещё нет.
