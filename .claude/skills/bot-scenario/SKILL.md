# Бот — паттерн сценария

## Архитектура

- aiogram 3: Router на сценарий, StatesGroup, файл = сценарий (`scenarios/seizure.py`).
- Бот НЕ ходит в БД. Только API с сервисным токеном (env BOT_API_TOKEN),
  от имени привязанного parent_id. Клиент API — один модуль `bot/src/api.py`.
- Все тексты — ТОЛЬКО в `bot/src/texts.py` (согласуются с мед. командой).
  Строка в хендлере = ошибка ревью.

## Шаблон сценария

1. Вход — кнопка главного ReplyKeyboard.
2. 2–4 шага, инлайн-кнопки где возможно, на каждом шаге кнопка «Отмена» (сброс FSM).
3. Валидация чисел с переспросом: кетоны 0–12 ммоль/л, вес 2–150 кг,
   длительность приступа — кнопки-диапазоны + ручной ввод.
4. Финал: POST в API (source=bot) → короткое подтверждение «Записано ✓» → сброс FSM.
5. Ошибка API → «Не получилось сохранить, попробуйте ещё раз», данные шага не терять.

## Сценарий «Еда» (особый)

«Из меню на сегодня» → список menu_items кнопками → отметка eaten.
«Не по меню» → свободный текст → POST /ai/parse → карточка разбора →
Подтвердить / Исправить / Отмена. Сохранение ТОЛЬКО после «Подтвердить»
(source=ai_parsed). AI недоступен → предложи выбор из меню, не падай.

## Запреты (ТЗ §7.5)

Бот не показывает параметры назначения, не считает, не отвечает на медицинские
вопросы. Нераспознанный текст вне FSM → стандартный ответ из texts.py со ссылкой
на Mini App и напоминанием обратиться к врачу.

## Напоминания

Логика — в worker (reminders_cron, */5 мин, TZ Asia/Tashkent), бот только отправляет.
Настройки времени — в веб-кабинете, не в боте. Дефолт «нет записей за день» — 20:00, одно, мягкое.
