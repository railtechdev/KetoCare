# Бот — паттерн сценария

## Архитектура

- aiogram 3. Сценарии ввода — `apps/bot/src/bot/handlers/scenarios.py`
  (StatesGroup на сценарий: `Seizure`, `Ketones`, `Weight`, `Meal`, `Medication`,
  `Wellbeing`, плюс общий шаг `When`), привязка и выбор языка —
  `handlers/start.py`, нераспознанное — `handlers/fallback.py` (подключается
  последним, только личные чаты: в группах бот молчит). Общие шаги (привязка
  сценария, запись, меню) — `deps.py`; клавиатуры — `keyboards.py`.
- Бот НЕ ходит в БД. Только API, и только через `apps/bot/src/bot/api.py`.
- Аутентификация **двухключевая** (ADR-0009): сервисный токен `BOT_API_TOKEN`
  (заголовок `X-Bot-Token`) сам по себе открывает только погашение кода и обмен
  секрета на сессию; вместе с **секретом привязки** он меняется на access-токен,
  суженный до одного ребёнка (`patient_scope`). Секреты лежат в Redis
  (`storage.py`, `BindingStore`) и не восстанавливаются — терять их нельзя;
  кеш сессий в памяти процесса — можно.
- Боту открыт только перечень **`BOT_ALLOWED_ROUTES`**
  (`apps/api/src/api/deps/bot.py`), список разрешающий. Новый вызов из бота =
  строка в этом списке + тест в `apps/api/tests`, называющий бота потребителем
  (как в `test_ai_parse.py`, `test_family_language.py`). Тест бота на подделке
  API стык не проверяет: так кнопка «Лекарства» с первого дня отвечала «не
  удалось сохранить» — маршрута не было в списке.
- Лимиты частоты у бота свои (`api/ratelimit.py`): общий потолок по адресу
  плюс ведро на человека Telegram (погашение кода) и на привязку (обмен
  секрета) — `hit_bot_bucket`. Новый «открытый сервисному токену» вызов без
  своего ведра один шумный чат превратит в отказ для всех семей.

## Несколько детей в чате (ADR-0048)

- У каждого ребёнка своя привязка и свой секрет: `bot:bindings:<chat>` — хеш
  «patient_id → привязка», `bot:active:<chat>` — выбранный ребёнок. Порядок
  детей — по `Binding.linked_at` (как в Mini App), не по имени.
- **Сценарий начинается с `begin_scenario(message, state, store)`**, а каждый
  следующий шаг берёт привязку через `scenario_binding(...)`, а не
  `store.get()`: выбранный ребёнок может смениться посреди сценария (кнопка 👶,
  присланный код), и запись обязана уйти тому ребёнку, про которого начата.
  Ребёнка больше нет в чате — сценарий закрывается, запись не уходит никому.
- Когда детей двое и больше, шаги и эхо называют ребёнка по имени без фамилии
  (`child_label`, `named`, `SAVED_FOR`); у одного ребёнка имени в переписке нет.
- Отзыв привязки (`LinkRevokedError`) → `link_revoked`: забывается привязка
  ОДНОГО ребёнка, остальные живут дальше.

## Тексты и язык (ADR-0052)

- Строки — ТОЛЬКО в каталогах `texts_ru.py` и `texts_uz.py` (узбекский —
  латиница): одно имя, те же `{подстановки}`, в обоих сразу — иначе падает
  `apps/bot/tests/test_language.py`. Хендлеры, общие шаги и клавиатуры пишут
  `texts.X`: модуль `texts.py` своих строк не держит и отдаёт строку каталога
  языка текущего обновления (`ContextVar` в `i18n.py`, ставит
  `LanguageMiddleware`). Строка в хендлере = ошибка ревью.
- Фильтр кнопки — `F.text.in_(i18n.variants("BTN_…"))`, а не
  `F.text == texts.BTN_…`: фильтры считаются при импорте, а клавиатура на
  прежнем языке обязана работать.
- Язык — свойство человека на сервере (`users.language`); бот держит копию в
  Redis на 5 минут (`LANGUAGE_TTL_S`). Выбор — кнопка «🌐» в главном меню и
  `/language` (`handlers/start.py`); непривязанному языки показываются под
  объяснением про код.
- Тексты бота продуктовые (как пользоваться, подтверждения, напоминания,
  доступ) — их пишет и меняет разработка (решение заказчика 05.10.2026).
  Подпись клиники нужна только клиническому утверждению — что делать с
  ребёнком, как толковать значение; таких в боте быть не должно (ТЗ §7.5).

## Шаблон сценария

1. Вход — кнопка главного ReplyKeyboard. **Кнопка меню всегда побеждает**
   незаконченный сценарий: обработчики кнопок регистрируются раньше шагов, и
   каждый старт начинает с чистого состояния.
2. 2–4 шага, инлайн-кнопки где возможно, на каждом шаге «Отмена»
   (`keyboards.CANCEL_DATA`, один обработчик на все сценарии).
3. Валидация чисел — только диапазон, без толкования: кетоны 0–12 ммоль/л, вес
   2–150 кг (константы вверху `scenarios.py`). Длительность приступа — шкала
   из справочника (`GET /dictionaries/intake-options?scale=seizure_duration`,
   та же, что в анкете, ADR-0020) → `duration_option_id`; секунды
   (`duration_sec`) — только у измеренного («точно»), интервал со слов в секунды
   не пересчитывается.
4. Перед записью — шаг «Когда это было» (`ask_when`): момент события задаёт
   семья, «сейчас» ставится, только если она так ответила.
5. Финал — `deps.submit_log(...)`: POST в API → эхо введённого (не голое
   «Записано») → сброс FSM. **`source` бот не передаёт** — канал ставит сервер.
   Ключ `Idempotency-Key` и тело хранятся в данных FSM (`pending_write`) до
   успеха: повтор после «нет связи» отправляет ТУ ЖЕ запись байт в байт
   (ADR-0035). Отказ сервера (не транспорт) закрывает попытку — следующая будет
   новой записью с новым ключом. Свой POST мимо `submit_log` не пишется.
6. Незаконченный сценарий живёт в Redis не дольше суток (`FSM_TTL` в
   `main.py`, тот же срок, что у ключей повтора на сервере;
   `tests/test_fsm_ttl.py`). Хранилище FSM — только `build_storage`.

## Сценарий «Еда» (особый)

«Из меню на сегодня» → позиции дня кнопками → отметка `eaten`; после отметки —
остаток плана заново с сервера (серия отметок, выход «Готово»). Ответ 404/409
(`plan_changed` — план пересохранили без позиции) — не «сервис недоступен»:
бот показывает план, какой он теперь.
«Написать словами» (есть и там, где плана нет) → свободный текст →
`POST /ai/parse` → разобранное названиями и граммами → Подтвердить / Исправить /
Отмена. Сохранение ТОЛЬКО после «Подтвердить», в `POST /logs/meals` уходит
`ai_job_id`, а не структура. `rate_limited` → «на сегодня хватит», прочий отказ →
«разбор недоступен» с меню; бот не падает.

## Запреты (ТЗ §7.5)

Бот не показывает параметры назначения, не считает, не отвечает на медицинские
вопросы. Нераспознанный текст вне FSM → `UNKNOWN_INPUT` (или `_NO_APP`, если
Mini App не настроен) с меню; присланный текстом код привязки разбирается до
отбойника. Выдавать коды доступа из бота нельзя — сервер отвечает 403
(`routers/access_codes.py`), закрытия доступа в `BOT_ALLOWED_ROUTES` нет.

## Напоминания

Логика и отправка — в воркере (`worker/reminders`, `reminders_cron` каждые 5 мин,
сутки — по `TZ` проекта): воркер шлёт сообщение в Telegram сам, на языке
взрослого (`worker/reminders/texts.py`, паритет — `test_texts_catalog.py`); бот
в этом не участвует. Время напоминаний семья настраивает в **Mini App** (блок
«Напоминания» на главной) или в кабинете — не в боте (ADR-0044). Напоминание
уходит, только если записи за день ещё нет.
