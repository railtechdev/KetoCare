# AI-модуль — правила

## Единственная дверь к Claude API

Все вызовы — через `apps/worker/src/worker/ai/client.py`: ретраи (3, экспоненциально),
таймауты, учёт tokens_in/out и cost_usd → запись в ai_jobs (всегда, включая ошибки).
Имена моделей — только из env (AI_MODEL_FAST — parse, AI_MODEL_SMART — summary/assistant).
Хардкод имени модели = ошибка.

## Псевдонимизация (критично)

`pseudonymize(payload)` — единственная точка подготовки данных пациента.
В промпт НИКОГДА не попадают: ФИО, контакты, chat_id, email.
Пациент = "patient <short-id>, возраст X лет Y мес, пол".
На функцию есть юнит-тест, проверяющий отсутствие запрещённых полей — не ломай его,
при добавлении полей в payload расширь и тест.

## Промпты

Файлы в `apps/worker/src/worker/ai/prompts/*.md`, меняются только отдельным PR (ревью человека).
Не генерируй и не правь промпты «заодно» с кодом. В промптах ассистента и сводки —
жёсткие запреты: дозировки, изменение диеты/лекарств, интерпретация симптомов, диагнозы.

## Человек-в-контуре

- parse_free_text → результат показывается пользователю, сохранение только после «Подтвердить».
- doctor_summary → только draft_md; в отчёты попадает approved_md после approve врача.
- Ничего из выхода модели не пишется в клинические таблицы напрямую.

## Лимиты и деградация

Лимит на пользователя (AI_USER_DAILY_LIMIT) и дневной бюджет (AI_DAILY_BUDGET_USD);
превышение → error code rate_limited с понятным русским текстом.
AI недоступен → функции деградируют мягко: бот предлагает меню, ассистент пишет
«временно недоступен», остальная система не затронута.

## Выход parse_free_text

Строгий JSON по схеме ТЗ §10.3, валидация pydantic; невалидный → один повтор
с текстом ошибки; второй провал → clarification_needed.
