# Воркер и AI-модуль — правила

Подробности и устройство — `apps/worker/README.md`; ADR-0019, 0021–0024.
Задачи регистрируются в `apps/worker/src/worker/main.py` (`WorkerSettingsARQ`):
новая задача без строки в `functions`/`cron_jobs` молча не выполняется.

## Единственная дверь к Claude API — `AiClient`

`apps/worker/src/worker/ai/client.py`, метод `ask(kind=…, requested_by=…,
patient_id=…, system=…, payload=…, user_text=…)`. Своего `anthropic.Anthropic`
в задаче быть не должно. Клиент сам делает всё, о чём нельзя вспоминать в
каждой задаче:

- `pseudonymize(payload)` и `scrub_free_text(user_text)` — вызывающий их не зовёт
  и обойти не может;
- предохранители под блокировкой бюджета (`jobs_repo.lock_budget`): дневной
  бюджет проекта `AI_DAILY_BUDGET_USD` (все задачи) и суточный предел
  пользователя `AI_USER_DAILY_LIMIT` — только для `USER_LIMITED_KINDS`
  (assistant, doctor_summary, content_draft; разбор еды не ограничен). Сутки —
  по `TZ` проекта, не «24 часа»;
- строка `ai_jobs` с бронью стоимости ДО вызова, токены и `cost_usd` после —
  включая неудачу и ответ без текста;
- ретраи (`MAX_RETRIES = 3`) делает SDK — свой цикл поверх не писать (было бы 9);
  таймаут 60 с по умолчанию;
- модель — из env (`AI_MODEL_FAST` для `parse_meal`/`parse_event`,
  `AI_MODEL_SMART` для остальных). Пустое значение — `NotConfigured`, не
  подстановка. Хардкод имени модели = ошибка.

Цены — `ai/pricing.py` (сверены с прайсом Anthropic), не в env: модель без цены
к работе не допускается (`assert_priced`), иначе бюджет считал бы её нулём.
Новая модель → строка в `pricing.py`.

Превышение → `AiLimitExceeded`; задача возвращает конверт
`{"status": "limited", "message": …}`, API превращает его в `rate_limited`.
Застрявшие в `RUNNING` строки закрывает cron `close_stuck_ai_jobs` (бронь не
снимается — деньги ушли).

## Псевдонимизация

`ai/pseudonymize.py` — единственная точка. Снимает на любой глубине ключи из
`FORBIDDEN_KEYS` (имена, `birth_date`, контакты, chat_id…), заменяет меткой любой
словарь с `id` + `birth_date`, пациент под ключом `patient` → строка
`patient <short-id>, возраст X лет Y мес, пол`. Свободный текст и строковые
значения чистятся от почты, телефонов и `@username` (ADR-0019). Новое поле с
идентифицирующими данными → в `FORBIDDEN_KEYS` + `tests/test_pseudonymize.py`.
Данные, которые должны дойти до модели (рост, пол сводки), не кладутся в
словарь, похожий на человека: у сводки они под `anthropometry`.

## Промпты

`ai/prompts/*.md` (assistant, parse_free_text, doctor_summary, content_draft) —
меняются только отдельным PR с ревью человека (ТЗ §10.4). Не правь их «заодно»
с кодом.

## Человек в контуре

Ничего из выхода модели не пишется в клинические таблицы напрямую.

- **parse_free_text** (`ai/parse.py`): строгий JSON, pydantic; `product_id`
  сверяется со списком, переданным в промпт. Невалидный ответ → один повтор с
  текстом ошибки (отдельная строка `ai_jobs`), второй провал →
  `clarification_needed`. Ничего не сохраняет: запись делает
  `POST /patients/{id}/logs/meals` с `ai_job_id`, структуру сервер берёт из журнала.
- **assistant_reply** (`ai/assistant.py`) — порядок воронки и есть защита,
  не переставлять: поиск по базе знаний (ничего не нашлось → модель не
  вызывается, ответ `NO_MATERIAL`) → `guard.check(вопрос)` → модель →
  `guard.check_answer(ответ)` → сверка `[[kb:id]]` с переданными статьями
  (выдуманная ссылка = блок). Наружу всегда `Answer`: текст или шаблон
  `DOCTOR_TEMPLATE`. Заголовки статей (`source_articles`) API добавляет при
  чтении переписки (`kb_repo.titles_for`), воркер хранит только slug'и.
- **doctor_summary** (`ai/summary.py`): ряды и все агрегаты собирает API
  (`api/services/summaries.py`), воркер их не пересобирает. Две проверки
  черновика: `core.textguard` (лексическая, по предложениям) и
  `ai/grounding.py` (каждое число — из переданных; разности и доли не
  выводятся). Черновик сохраняется всегда, с находками; в отчёт идёт только
  `approved_md`. На утверждении (`routers/summaries.py`) фильтр работает заново:
  жёсткая находка в неизменённом предложении модели запрещает, в предложении
  врача — предупреждение, утверждение повтором с `acknowledged_findings`; сбой
  фильтра запрещает всегда.
- **content_draft** (`ai/content.py`): состав закрыт, `grounding` с
  `only_masses=True`, ничего не сохраняется. Аномалии базы продуктов — арифметика,
  не модель.

## Постфильтр помощника — `ai/guard.py`

Четыре запрета ТЗ §10.4 (дозировки, изменение терапии, толкование симптомов,
диагнозы); каждое правило — произведение двух признаков (`lexicons.py`), одно
слово ничего не блокирует. `check_answer` сначала проверяет язык: ответ не
по-русски (доля русских букв в ответе и в КАЖДОМ предложении, нерусская
кириллица, три латинских слова подряд) — блок `UNREADABLE`, правила его не
читают. Вопрос по-узбекски не блокируется (ADR-0052). Любая внутренняя ошибка —
блок (`fail-closed`). Правка правил — только вместе с золотым корпусом
`tests/data/assistant_guard_cases.yaml`: в нём и обязанное блокироваться, и
обязанное проходить.

База знаний: `docs/knowledge-base/clinical/` защищён хуком (подписывает
медкоманда), `product/` пишет агент; индекс — `make kb-index`.

## Постановка задач из API

Задача, вызванная записью, уходит после коммита: `api.after_commit.defer(session,
"<task>", *args)` либо явный `commit` и затем `queue_service.enqueue` в
`try/except` с веткой на отказ очереди (строка не должна остаться в
«готовится»). Синхронное ожидание (`/ai/parse`, черновик рецепта) —
`queue_service.run(…, timeout_s=…)`. Аргументы задачи — строки/JSON.

## Уведомления в Telegram (`reminders/notify.py`)

Задачи: `notify_family`, `notify_family_joined`, `notify_family_nudge`,
`notify_family_menu_composed`, `notify_password_changed`,
`notify_account_security` (события из `ACCOUNT_SECURITY_EVENTS`, текст без имён
и чисел), плюс `reminders_cron` каждые 5 минут. Тексты — только в каталоге
`reminders/texts.py` (`RU`/`UZ`, одинаковые ключи и подстановки — держит
`tests/test_texts_catalog.py`); язык — `users.language` адресата
(`chat_languages`, `parent_language`). В сообщениях нет чисел назначения и
советов (ТЗ §7.5). Нет `BOT_TOKEN` — задача тихо возвращает 0.

## Файлы и отчёты

- `render_report` (`reports/task.py`): данные отчёта приходят аргументом из API,
  второй сборки нет. Если строка задачи исчезла, пока PDF собирался
  (`erase_patient`), файл удаляется сразу — сирота с ФИО не остаётся
  (`tests/test_report_task_orphan.py`).
- `purge_files` (cron 03:30) снимает просроченные PDF и байты удалённых **фото
  рецептов** через `ATTACHMENT_PURGE_DAYS`. **Документы пациента не убираются
  никогда** (ответ клиники на вопрос 25): физически их снимает только
  `core.tools.erase_patient`. Строки остаются всегда.
- `purge_idempotency_keys` — раз в час (сохранённые ответы содержат данные
  ребёнка, ADR-0035).
