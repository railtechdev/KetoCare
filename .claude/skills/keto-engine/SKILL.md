# Keto Engine — процедура изменений

Ядро — единственное место, где ошибка = клинический риск. Порядок обязателен.

## Перед любой правкой

1. Прочитай `docs/medical/calculation-engine-spec.md`. Если файла нет (сейчас его нет)
   или значения нет — бери дефолт из ТЗ §6.2, помечай `# TODO(med): подтвердить`,
   добавь вопрос в `docs/medical/OPEN_QUESTIONS.md` (формат: дата, вопрос, где используется дефолт).
2. Прочитай `packages/keto_engine/src/keto_engine/constants.py`, эталоны в
   `docs/medical/reference-cases/` и тесты пакета
   (`test_reference_cases.py`, `test_properties.py`, `test_engine_internals.py`).

## Инварианты (нарушение = ошибка задачи)

- Пакет чистый: никаких импортов из core/api, никакого I/O, только frozen dataclass in/out.
- Формула соотношения: `F = R × (P + C)`. В solve линеаризуется как `F − R·P − R·C = 0`.
- Дефолтные константы живут ТОЛЬКО в `constants.py`, каждая с `TODO(med)`: энергия 9/4/4 ккал/г;
  допуск R ±0.15; kcal ±5%; округление масс до 1 г; мин. масса ингредиента 2 г;
  net carbs по умолчанию выключены. Числа в коде движка вне constants.py — ошибка ревью.
- `solve` — scipy.optimize.linprog (HiGHS). При infeasible — определить нарушающее
  ограничение поочерёдным ослаблением и вернуть `InfeasibleError` с человекочитаемой
  причиной на русском («С выбранными продуктами недостижимо соотношение 4:1 — …»).
- Аллергии фильтрует вызывающая сторона; ядро о них не знает.

## Проверка выполнимости назначения

`max_non_fat_grams(ratio, kcal)` — не медицинское правило, а тождество: из
`F = R·(P+C)` и коэффициентов Атуотера следует `P + C = kcal / (9R + 4)`.
Используется в `/prescriptions` для отсева арифметически невыполнимых назначений
(цель по белку выше этой величины недостижима ни при каком наборе продуктов).
Добавляя подобные проверки, убедись, что это именно тождество, а не подобранный
порог: порог = выдуманная медицинская константа (нарушение правила 1).

## После правки — всегда

1. Подними `ENGINE_VERSION` (semver: fix → patch, новая логика → minor,
   изменение результатов существующих расчётов → major).
2. Прогони эталоны: `make test-engine` (один кейс — `uv run pytest packages/keto_engine -k <имя>`).
   Все эталоны зелёные. Эталонный тест упал → чини код. Менять эталон можно ТОЛЬКО по новой
   версии медицинской спецификации, и делает это человек (хук блокирует правку `docs/medical/`).
3. Property-тесты (hypothesis) обязаны сохраниться: `verify(solve(x))` в допусках;
   `scale(r, 1.0) == r`; монотонность kcal по массам.
4. Покрытие пакета — 100% строк (`make coverage-engine`).
   Пункты 1-2 проверяет хук `.claude/hooks/engine-guard.sh` сразу после правки:
   он гоняет тесты ядра и требует bump ENGINE_VERSION. Не обходи его — он ловит
   ровно то, что иначе всплывёт в CI через десяток правок.
5. В PR: что изменилось в математике, почему, ссылка на пункт спецификации/ТЗ.
